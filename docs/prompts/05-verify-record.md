# 模板 05 — 验证门禁 + 记录沉淀(任务收尾)

## 何时用
每个任务实现完成后收尾;或用户说"跑一遍验证/记录一下"时。**不允许跳过**。

## 提示词正文(粘贴区)

```
按 lopezpress 的 AI 协作标准完成本任务的验证与记录。

【执行要求】
1. 验证门禁,逐项贴结果(不允许只说"通过"):
   - go build ./...
   - go vet ./...
   - go test ./...
   - web: npx tsc --noEmit
   - web: npm run build
   任何一项失败:修到绿,或明确记录未解决项 + 原因,不许带病标记完成。
2. 行为验证:本次改动影响的端点/页面/交互,实际跑起来验证,贴证据
   (curl 状态码 / 服务日志 / 截图路径)。运行态服务注意:改了 .env 或代码必须重启后端再验。
3. 记录沉淀(按改动性质选,可多项):
   - PROGRESS.md:追加轮次条目(照旧轮格式:目标/改动/测试/验证)
   - docs/TODO.md:勾销完成项、更新状态
   - .workbuddy/memory/YYYY-MM-DD.md:追加本次记录(改了什么/验证结果/遗留)
   - 发现新陷阱:追加 HANDOVER.md §7 + memory/MEMORY.md
   - 方向性决策:docs/decisions/ 新增编号文件(append-only)
4. 最终汇报格式:结论先行(做了什么 / 验证结果表 / 遗留项),证据附后。
```

## 预期产出
- 五命令门禁结果(逐项)
- 行为验证证据
- 对应记录文件更新
- 结论先行的最终汇报
