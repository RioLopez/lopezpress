# 决策 0006：邮箱验证做全套，但默认关闭并明确标注"测试"

> 时间：2026-10-24（第 79 轮）｜状态：Accepted｜规格：`docs/specs/37-email-verification.md`

## 背景

站点的三种"证明你是你"的路径此前都有洞：

| 场景 | 第 79 轮之前 |
|---|---|
| 注册 | 邮箱随便填，不验证真实性 |
| 忘记密码 | **无自助路径**，只能找管理员重置（root 密码甚至只能走离线 CLI） |
| 换绑邮箱 | `PUT /api/auth/me` 直接改，无任何验证 |

用户的指令是明确的三条：

> "把全套都做好吧，不过同样的，属于测试功能，目前默认关闭，并且提示是测试，然后呢，管理员也可以开启和关闭之类的。"

这句话把方案框死了：**功能必须完整，但默认不启用。**

## 决策

### D1 三条流程一起做，不做半套

只做注册码会留下"忘记密码还是只能找管理员"这个更大的窟窿。三条流程共用一套验证码基础设施（`IssueEmailCode` / `ConsumeEmailCode`），差异只在 `purpose`：

| purpose | 触发点 | 成功后的副作用 |
|---|---|---|
| `register` | 注册页 | 建号并直接签发 JWT |
| `reset_password` | `/forgot-password` | 改密码 + **bump `token_version`**（所有会话失效） |
| `change_email` | 设置页换绑 | 改邮箱 + 给**旧**地址发变更通知 |

### D2 默认关闭，且"关闭"是一等状态

`site_configs.email_verify_enabled` 默认 `false`。关闭时：注册不带 `code` 也能过、`/forgot-password` 前端显示"本站未开启邮箱验证，请联系管理员"、验证码端点返回 403。前端在开关旁边显示 `测试功能` 徽标 —— 用户明确要求"提示是测试"。

### D3 开关是 root 专属

和 `allow_register` / `smtp_*` 同级。理由：开这个开关意味着**任何匿名访客都能让这台 1 核机器发信**，这是滥用面而不是展示偏好。普通 admin 保存站点配置时这三个字段从库值继承。

### D4 六位数字的强度靠约束，不靠长度

六位数只有 100 万种，必须叠加四层限制：

1. 每个码最多 5 次错误尝试，之后作废；
2. 一次性（`used_at` 置值即失效）；
3. 绑定用途（HMAC 的输入含 `purpose`，注册码不能拿去重置密码）；
4. 库里只存 HMAC（key = `JWT_SECRET`）——裸 sha256 等于一张 10^6 的彩虹表。

另外两道频率闸：同邮箱 60 秒冷却（**存在表里**，重启不清零，否则 kill 进程就能刷爆别人收件箱）+ 同 IP 每小时 10 封（防换邮箱刷）。

请求验证码永远返回同一句话，不透露邮箱是否已注册。

### D5 顺序固定：冷却 → 查 SMTP → 发信 → 落库

`sendMailFn` 对通知类把"没配 SMTP"当成功（对通知合理：不该因为没配邮件就让审核失败）。验证码照搬这个语义就是骗人，所以：

- `requireSMTP` 在发信前显式检查，未配置返回 **503** 并说明原因；
- 先发信、后落库 —— 发信失败不留"有效但没人收到"的行；
- 发送成功的旧码立即作废（两条有效码等于把猜测空间翻倍，且用户点了"重发"再输第一封的数字会困惑）。

### D6 堵住旁路：`PUT /api/auth/me` 不许改邮箱

这是全套里最容易漏的一条。前端把邮箱改成只读 + "更换"面板，但后端 `applyIdentityChange` 原本仍接受 `email` 字段 —— **一次 PUT 就绕过整套验证码**。现在开关打开时直接 403，并有单测。

推广成规则：**凡是"换了个入口做同一件事"的新流程，都要回头堵住旧入口。**

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 只做注册验证码 | 忘记密码仍无解，价值不完整 |
| 改用邀请码（不依赖邮件送达） | 用户明确要"全套"，且自建站通常已有 SMTP；邀请码另作后续选项 |
| 默认开启 | 直接违背用户指令；且很多自建站没配 SMTP，一开就是"注册全挂" |
| 6 位码 + 图形验证码 | 多一个依赖与一层前端组件，收益不如"5 次作废 + 双频限流" |
| 邮件里放一次性链接（token in URL） | 需要站点 URL 绝对正确 + 额外的落地页；六位码在移动端更好输入 |

## 代价与已知不足

- **未用真实 SMTP 验证过**：只用 `scripts/fakesmtp.py`（故意不实现 STARTTLS）走过全流程。上线前必须用真邮箱验 TLS 与退信。
- 无退信处理：地址写错时用户只能等 60 秒重发，系统不知道信没送到。
- "同 IP 每小时 10 封"是内存固定窗口：重启清零，多实例各算各的（当前单实例）。
- 冷却按邮箱地址存，**重跑冒烟脚本必须换地址后缀或重建 DB 副本**，否则第一次请求就 429。

## 验收证据

- 单测（`internal/services/email_codes_test.go`）：开关关闭时注册不需要码、开启时缺码被拒、5 次错误后正确码也失效、用途不可互换、开着验证时 `PUT /api/auth/me` 改邮箱 403、重置密码 bump 版本、换绑成功。
- 隔离真机冒烟 **28/28**：真收信取码 → 注册 → 登录 → 找回密码 → 用新密码登录 → 换绑邮箱 → 旧邮箱收到通知 → 关掉开关后注册不再要码 → 普通 admin 关不掉开关。
