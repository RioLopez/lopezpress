## 5. 汇总

**口径（脚本按行重算，不靠肉眼）**：每行取 S/T/R/E/I/V 六格；`—` 视为该维不适用。
- **全完整**：六维全 `✅` 或 `—`
- **有短板**：至少一个 `⚠️`，但没有 `❌`
- **有缺口**：至少一个 `❌`

| 维度 | 数量 |
|---|---|
| 功能条目 | **46**（第 79 轮 +2：I-04 升级为完整图库、新增 I-09 邮箱验证；旧表 44 项含 W-01～W-10） |
| 全完整（六维 ✅/—） | 1 |
| 有短板（⚠️ 无 ❌） | 33 |
| 有缺口（含 ❌） | 12 |

> 重算命令见本文件末尾「校验方法」。**旧表曾写 16/16/12，那是肉眼估的，与逐格重算不符**——矩阵类数字一律以脚本为准。

**结论**：46 项里只有 1 项六维全 ✅，说明"六维全部写清"这个门槛对本项目偏高（很多维度对某功能本就不适用，或"写清"的成本大于收益）。真正该盯的是**有 ❌ 的那 12 项**：`R-04`/`R-06`/`R-08`/`R-11`（读者链路）、`W-03`/`W-04`/`W-07`/`W-08`/`W-09`（写作链路）、`A-12`/`A-13`（后台）、`I-02`（SEO/OG）。

**已明确不追的**：R-11 评论（用户决定不做）、I-02 SEO/OG（纯 SPA 抓不到卡片，需 SSR，代价与"轻量"定位冲突）。

**第 79 轮的变化**：I-04 从"上传能跑"升级成有 spec / 测试 / 真机验证 / 后台管理的完整图库；I-09 是全新条目（邮箱验证），唯一 ⚠️ 是"真实 SMTP 未验"。这两项都**没有降低**任何既有维度的评分——即没有为了新功能牺牲老功能的完整性。

## 7. 校验方法（汇总数字怎么来的）

本文件的汇总数字**不许手数**（第 79 轮校正时发现旧表的 16/16/12 与逐格统计不符）。改完表格后跑：

```bash
python - <<'PY'
import io, re
s = io.open('docs/FEATURE_DESIGN_MATRIX.md', encoding='utf-8').read()
rows = []
for ln in s.split('\n'):
    if not ln.startswith('|'): continue
    cells = [c.strip() for c in ln.strip().strip('|').split('|')]
    if len(cells) < 8 or not re.match(r'^[A-Z]-\d+$', cells[0]): continue
    rows.append((cells[0], cells[-7:-1]))          # 倒数第 7..2 格 = S/T/R/E/I/V
print("条目数:", len(rows))
print("全完整:", sum(1 for _, d in rows if all(x in ('✅','—') for x in d)))
print("有短板:", sum(1 for _, d in rows if not all(x in ('✅','—') for x in d) and not any(x=='❌' for x in d)))
print("有缺口:", sum(1 for _, d in rows if any(x=='❌' for x in d)))
PY
```

三档之和必须等于条目数，否则就是把某行写成了 7 格或 9 格（表格错位）。
