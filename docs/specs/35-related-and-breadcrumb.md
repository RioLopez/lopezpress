# Spec 35 — 相关文章与面包屑

> 状态：Implemented（第 52 轮）｜关联：`docs/COMPETITIVE_GAP.md`

## 1. 问题

第 50 轮的竞品对标把"内容运营"标成"有但浅"，具体缺口：

1. **读完一篇就没有下一步**——只有"上一篇/下一篇"（时间序），读者对某主题感兴趣时没有横向出口。
2. **阅读页没有位置感**——不显示"首页 / 分类 / 标题"，从搜索结果直接进来的人不知道自己在站内哪一层。

## 2. 目标

- 阅读页底部出现"相关文章"（≤5 篇，已发布）。
- 阅读页标题上方出现面包屑：`首页 / 分类名`（无分类时只有"首页"）。

## 3. 相关文章规则

**WHEN** 请求 `/api/posts/{id}/related` **THEN** 返回满足以下任一条的**已发布**文章，排除自身：

- 同 `category_id`；
- 共享任意一个标签。

排序：`view_count DESC, created_at DESC`（没有阅读历史模型时，"读得多"是最诚实的相关性近似）。

| 决定 | 理由 |
|---|---|
| 一条 SQL，不在 Go 里排序 | 1 vCPU 上避免把候选集拉进内存 |
| 只返回已发布 | 否则读者点进去得到 404 |
| 无分类、无标签时返回 `[]` | 这是正常状态，前端直接隐藏该区块 |
| 未知 id → 404 | 调用方问的是一篇不存在的文章，不是"没有相关" |

## 4. 面包屑规则

- **WHEN** 文章有分类 **THEN** 显示 `首页 / <父分类> / <分类>`，末级分类可点，跳到 `/?category=<分类名>`（第 74 轮起用名字，`<id>` 形式仍兼容；父级是纯文本）。
- **WHEN** 文章无分类 **THEN** 只显示"首页"。
- 全部走 SPA 内跳转，不做整页刷新。

## 5. 边界

| 场景 | 结果 |
|---|---|
| 站内只有一篇文章 | `related = []`，区块不渲染 |
| 同标签文章全部是 pending/banned | 不返回，区块可能为空并隐藏 |
| 文章分类为 NULL（历史数据 `category_id = 0` 已在本轮修正为 NULL） | 只按标签匹配 |
