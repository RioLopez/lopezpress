# 竞品对标：缺什么、哪里浅

> 对标对象：**WordPress**（插件生态上限）、**Ghost**（现代托管博客标杆）、**Halo**（Java 生态、中文社区最常被拿来比）、**Hugo / Hexo**（静态站代表）。

## 2. 完全缺失（竞品普遍有，我们没有）

| # | 功能 | 谁有 | 买家影响 | 做起来的代价 |
|---|---|---|---|---|
| G-1 | **主题/外观体系** | WP、Ghost、Halo、Hugo 全有 | 买回来和演示站一模一样，不能体现个人风格 | **高**（要抽模板层，前端要重构） |
| G-2 | **修订历史 / 版本回滚** | WP（每次保存一版）、Ghost、Halo | 改坏了没法回退，只能凭记忆重写 | 中（每次保存存一份 body 快照，加清理策略） |
| G-3 | **草稿态** | 全部 | 写一半只能存"私密"，语义不对 | 低（加一态 + 编辑器按钮） |
| G-4 | **定时发布** | WP、Ghost、Halo | 想早上 8 点发，只能人肉守着 | 中（惰性判定可免 ticker） |
| G-5 | **导入器**（WordPress WXR / Markdown 批量） | WP、Ghost、Halo、Hexo | **换不过来**——最大的销售阻碍 | 中（解析 + 去重 + 保留时间） |
| G-6 | **OG/社交分享卡片** | 全部（含静态站） | 分享到微信/微博是一条光秃秃的链接 | **高**（纯 SPA 需 SSR/预渲染） |
| G-7 | **定时 / 异地备份** | WP 插件、Halo 内置、Ghost 托管 | 靠站主自觉，数据安全无保障 | 中（cron + 保留 N 份 + WebDAV/S3） |
| G-8 | **评论** | WP、Ghost、Halo | 读者无法互动（我们明确不做，属定位取舍） | 高（反垃圾、审核、通知都要做） |
| G-9 | **媒体加工**（缩略图/裁剪/alt/替换/批量） | WP、Ghost、Halo | 传 2MB 原图直接给读者，移动端慢；没有 alt 不利无障碍 | 中（Go 图像库 + 存储变体） |
| G-10 | **2FA / 登录设备管理** | WP 插件、Halo 内置 | 账号只靠密码保护 | 中（TOTP + 设备表） |

## 3. 有，但深度不够（这是最值得补的一类）

| # | 功能 | 我们的现状 | 竞品深度 | 具体缺什么 |
|---|---|---|---|---|
| D-1 | **编辑器** | 裸 textarea + 分栏预览 + 代码复制 | Ghost 的卡片：图库、视频、书签、callout、toggle、产品卡；WP 块：栏目、表格、嵌入 | **无工具栏**（加粗/链接/图片全靠手写语法）、无粘贴上传、无拖拽上传、无表格/脚注快捷、无嵌入卡、无全屏专注模式 |
| D-2 | **SEO** | slug + sitemap + RSS + robots | meta description / OG / canonical / Article 结构化数据 / 301 管理 / 站点验证 | 除 slug 外**几乎全缺**；且 SPA 让客户端 meta 对爬虫无效（Google 能跑 JS，微信/Twitter 不能） |
| D-3 | **统计** | 总浏览 + 每篇浏览（已按人/天去重） | Ghost：实时访客、来源渠道、每篇转化、按会员分层 | 无**来源(referrer)**、无**时间趋势**（有 `post_views` 表却没做图表）、无热门榜、无导出 |
| D-4 | **搜索** | `LIKE %kw%` 扫 title/body/author | Halo：Lucene 索引 + 高亮 + 筛选；Ghost：内置全文 | 无摘要高亮（列表里高亮但无匹配片段）、无排序相关度、无按分类/标签组合、**千篇以上会明显变慢** |
| D-5 | **多作者** | 三层角色 + 审核队列 | WP 5 角色 + 协作编辑；Ghost 多作者 + 作者页统计 | 无共同编辑/锁定、无"编辑/投稿者"细分、作者页无统计、无作者简介完善度引导 |
| D-6 | **分类** | 两层树 + 预设 | WP 无限层 + 自定义分类法；Halo 多层分类 + 分类模板 | 只有两层；**无自定义分类法**（比如"系列""专栏"）；无分类封面/描述 |
| D-7 | **备份** | 手动 JSON + VACUUM 快照 | WP 定时 + 云盘；Halo 内置备份 | 无定时、无异地、无"备份完整性校验"、无恢复演练引导 |
| D-8 | **权限** | root/admin/user 三层，规则齐全 | WP 细到能力(capability) | 无细粒度权限（如"只能管自己分类"）、无 API Token（只有 JWT，脚本集成麻烦） |
| D-9 | **内容运营** | 置顶 + 分类标签 | WP/Halo：相关文章、系列、专题页、面包屑、阅读量排序 | **无相关文章**、无系列/专栏、无专题聚合页、无面包屑 |
| D-10 | **RSS** | 有，摘要固定 | WP：全文/摘要可切换、按分类输出 feed | 无全文/摘要开关、无分类 feed、无 podcast/JSON Feed |
| D-11 | **国际化** | 界面中英双语 | WP：WPML；Halo：多语言插件 | 文章**不能多语言**（一个站只能一种内容语言） |
| D-12 | **通知** | SMTP 安全通知（登录异常） | WP：评论/投稿通知 | 无"新投稿待审"邮件提醒、无"评论回复"通知（因为没评论） |

## 4. 我们比竞品强的地方（别为了抄而丢掉）

1. **部署体积**：单二进制 + 一个 `.db`，无 JVM/Node/PHP 运行时。Halo 要 JVM + 数据库，WP 要 LAMP。
2. **资源占用**：1 vCPU / 1 GB 能跑；Halo/WP 在这个配置上很吃力。
3. **权限模型的严谨度**：root 不可经任何 API 创建或提升、banned 文章冻结、备份导入有 root 闸门 —— 比很多小 CMS 严格。
4. **读者端细节**：目录高亮、阅读进度、阅读时长、灯箱、代码复制、上下篇，很多付费主题都没这么齐。
5. **浏览量去重**是服务端指纹（人/天），不是 PV 水分。

## 5. 该补的顺序（按"买家决策影响 × 实现代价"排）

| 优先 | 事项 | 为什么排这里 |
|---|---|---|
| 1 | **导入器（Markdown / WXR）** | 没有它，有存量博客的人第一步就走；代价中等 |
| 2 | **草稿 + 修订历史** | 写作安全感；两者共用一套"保存快照"机制，一起做最省 |
| 3 | **媒体加工（缩略图 + alt）** | 直接影响读者加载速度和无障碍，代价低 |
| 4 | **统计面板（趋势 + 来源）** | `post_views` 表已经在，只差聚合与图表；能立刻体现"专业感" |
| 5 | **编辑器工具栏 + 粘贴上传** | 从"会写 Markdown 的人能用"变成"所有人都能用" |
| 6 | **定时发布** | 惰性判定即可，不必上 ticker |
| 7 | **定时/异地备份** | 数据安全，买家最怕丢数据 |
| 8 | **OG/SEO** | 代价最高（要 SSR/预渲染），收益偏长期，最后做 |
| — | **主题体系** | 代价极高、与"轻"的定位冲突；**建议不做**，改为"3 套配色 + 2 种列表布局"的可配置项 |
| — | **评论 / 会员 / 插件市场** | 明确不做，靠定位取舍换轻量 |

## 6. 一句话结论

**我们是"深度合格的阅读器 + 明显偏浅的创作工具"。**

读者端：对标 Ghost 能打 8 分；作者端：对标 Ghost 只有 5 分；运营端（统计、SEO、迁移）：只有 4 分。真正拦住买家的不是功能列表少，而是 **G-5 导入器、G-3 草稿、G-2 修订、D-1 编辑器工具栏** 这四件"每天都在用但都缺一点"的东西。
